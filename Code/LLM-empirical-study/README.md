本文件夹为测试LLM是否有根据observation来划定相应related work的能力的代码。

主要实现的任务如下，共有三个子任务：

## RQ2：Testing the LLM's ability to, given an observation, identify the corresponding related work and solution.

### RQ2-1 ：Testing whether the LLM has the ability to generate corresponding related work.

Input： Observation

Output： Related works and core claim.

GroundTruth :  human generated Related works and core claim.

### RQ2-2: Testing the ability of the LLM to generate solutions

Input : Observation and related works (From human)

Output : Solution

GroundTruth :  human generated solution.

### RQ2-3: Test the influence of the LLM-generated "related work" and "human-related work" on generating the final solution.

Input : Observation and related works(generated by LLM)  /  Observation and related works(generated by human) 

Output : Solutions

Target: Compare the impact of the two input pairs on the solution.

内部实现逻辑如下：

1. 论文信息抽取，从典型论文集中抽取Observation、related works（core claims and works）、solution。作为人类逻辑的数据，即人类根据Observation找到相应的相关工作进行调研，了解该领域现状，然后根据上述信息生成solution。具体方式如下：利用openai样式的API调用方式抽取论文md中的所需内容。输入是一个存储md文件位置信息的jsonl文件夹地址。其根据唯一索引和位置找到相应的md，然后将内容提供给LLM模型（通过api）【使用deepseek-v4-flash】模型，开思考模式，要求输出严格的json格式】。然后分别提取论文的Observation，即人类专家开始要发表这篇论文的核心观察点，然后提取论文相关工作部分的claim和相应的支撑工作works（要求带有论文题目，作者，年份信息）；和原文使用的解决方案，方案必须合理，清晰，完整，逻辑完全符合原文描述，不能有缺失，替换等。以json格式存储在/home/zhangxujie/ai4research/ZXJ-workspace/Code/LLM-empirical-study/data下。然后将对应位置信息插入在原始的jsonl文件内。 提示词要点：严格遵循json格式要求，Observation不能包含具体的论文信息。related works要求包含claim和支持claims的works。必须包含其相关工作中所有的论文（题目，作者，年份）。solution必须完整，清晰，分为两个部分：思路，即采用这种解决方法的理由和内核思想；具体实现，即方法的具体每一步实现。jsonl文件样例：/home/zhangxujie/ai4research/ZXJ-workspace/Code/dataset/ADRS-and-let/md/pdf_mapping.jsonl

2. RQ1实验，输入是总体的jsonl文件，其中有human的提取数据，将其中各个论文的observation输入给LLM，让LLM生成相应的related work 的claim和相应的支撑works。要求提供works的名称和第一作者。为了后续评分的风格，长短等一致性，轮转将其他论文的related works的部分提供在提示词中（只保留第一作者即可，剩余作者和年份不用保留。让LLM仿照示例的风格，产出符合observation相关的相关工作部分，包括相关工作的核心claim和对应的works，以严格的json格式输出。需要有两种模式，第一种模式要求模型不能进行检索，只能根据自身的参数知识组织和输出。第二种模式要求模型可以根据observation检索相关论文，并且组织信息进行输出，分别输出到/home/zhangxujie/ai4research/ZXJ-workspace/Code/LLM-empirical-study/data/LLM_data/relatedworks_withsearch 和/home/zhangxujie/ai4research/ZXJ-workspace/Code/LLM-empirical-study/data/LLM_data/relatedworks_withoutsearch之中。 提供的人类结果必须不属于本论文，轮转替换，其目的是让模型了解相应的风格，长度等。保证输出风格的一致，而不是参考其内容。

3. RQ2,3实验，输入是一个jsonl文件的地址，其中有人类产出的observation，related works，solution的json地址，还有LLM产出的related works内容。现在需要实现solution的生成，输入分别是两种，第一种是human 的Observation + LLM的related works 的claim和相关论文；第二种是human 的Observation + human的related works 的claim和相关论文。都要求生成solution。solution分为两个部分，idea和implementation。分别代表根据observation的想法和具体实现。每次输入构造提示词将人类的idea和implementation也输出（不输入同一篇论文的，轮转将其他论文的内容提供）目的是让模型学习输出相同的表示，风格等，而不是参考其内容。两者得到的输出分别放置在/home/zhangxujie/ai4research/ZXJ-workspace/Code/LLM-empirical-study/data/LLM_data/solution_llm_re 和/home/zhangxujie/ai4research/ZXJ-workspace/Code/LLM-empirical-study/data/LLM_data/solution_human_re两个文件夹下。最后将得到的文件的地址插入原始jsonl文件。
